Claude Code 逆向分析

把本机安装的 Claude Code v2.1.287 完整拆开：提示词怎么装配、多 agent 怎么编排、上下文怎么管理、二进制里到底有什么。全程离线静态分析，未运行、未改动它。

一页速览

  1. 系统提示词是装配出来的，不是写出来的：6 个静态块 + 约 27 个动态块，每块有名、可空（null = 不注入，不是空串）、可单独开关。
  2. 块化直接服务缓存：最易变的计费头单独成第一块且不缓存，身份单独一块，其余合一块——提示词结构就是缓存结构。
  3. 表达层可插拔：Output Style 把"我是谁、我怎么说话"抽成对象（prompt + 每轮提醒 + 等待态提醒 + 是否保留编码纪律），与行为准则解耦。
  4. 同一意图给三级粒度：身份长文塑造、每轮一句话维持、状态特例纠偏。
  5. 规则偏"条件 + 替代 + 例子"，不靠大写禁令：e.g.(164) ＞ instead of(111) ＞ unless(92) ＞ NEVER(35)。
  6. 红线才上大写 NEVER：约 18 条，每条对应一个真实高频事故。
  7. 冲突显式裁决：Where these rules conflict with … these rules win.
  8. 把 harness 机制写进提示词：谁注入了 <system-reminder>、工具结果可能来自外部、hook 输出视同用户反馈。
  9. 异步子代理的返回体结构上没有"结果"字段——编造没有语法出口。
  10. 授权不可转发：批准后的动作要新开 agent 携带原文执行，顺带隔离"读不可信输入"与"执行特权动作"。
  11. 提示词即产品面：大段内容挂 tengu_* 开关，可灰度、可回滚、可 A/B。
  12. 三周内提示词正文几乎冻结：代码 +25%、开关 +13%，但 7 个小节逐字未变。

方法与可复现

Bun 的 --compile 单文件产物里，JS 源码是明文——模板字面量连反引号和 ${} 都保留，只有模块边界带字节码标记。所以不需要反编译器就能拿到全部提示词：

# 1. 切块：模块边界是 \x00 + "// @bun @bytecode"
python3 tools/carve_modules.py        # → 2174 个模块 + modules.json（含真实 chunk 名反查）

# 2. 抽字符串：状态机解析 '…' "…" `…`（含 ${} 嵌套）
python3 tools/extract_literals.py     # → 28,960 条模板字面量

# 3. 定位与取证
python3 tools/ctx.py <绝对偏移> 300 300   # 打印该偏移附近的源码原文
python3 tools/census.py               # 全库提示词句式统计

完整性核对：模块边界标记 2176 处、被引用的唯一 chunk 名 2175 个、我们切出 2174 个模块——三者一致，没有遗漏。模块名用「导出集合 ⊇ 导入名集合」反查，1266 个模块恢复出真实 chunk-*.js 名。

提示词是怎么装出来的

主装配函数返回两组块：shared（跨会话稳定）与 session（每轮可变）。静态块只有 6 个，动态块约 27 个——动态块可以返回 null，表示"这次不注入"。

最值得学的三点

  • 块名进缓存 key 与遥测：改一个块不会污染其它块的缓存。
  • 静态讲准则、动态讲处境：静态写 "NEVER/always"，动态写 "this session / right now"，用措辞把规则的有效期说清楚。
  • 同一个机制准备多档文案：system-reminder 说明、沟通规则各有 2~3 档，按运行形态切换，而不是写一篇覆盖所有情况的模糊长文。

表达层是可插拔的

一个 Output Style = {name, description, prompt, turnReminder, waitingTurnReminder, keepCodingInstructions}，内置 default / Proactive / Concise / Explanatory / Learning。工程纪律默认保留，只有显式声明才覆盖——默认安全。

Concise 风格里有一条裁决条款：Where these rules conflict with more general communication or formatting guidance elsewhere in your instructions, these rules win. 没有这句，风格提示词会在模型内部与系统提示词打平手。

规则怎么写：给条件、给替代、给例子

句式例子
禁令 + 例外No model turn unless the plugin asks for one.
禁止 + 替代Prefer the Edit tool for modifying existing files — it only sends the diff.
条件—动作If you did not check, say you did not check.
大写红线NEVER create documentation files (*.md) …
偏好排序Prefer denying the enclosing directories.
冲突裁决An explicit value always wins.
结论先行Report what actually happened, not what you intended.

多 agent 编排

  • 启动 ≠ 完成：Agent 工具的成功返回体里只有 status / agentId / outputFile，并明写 You know nothing about its results until that notification arrives。结果只能等 <task-notification> XML，且带 [SYSTEM NOTIFICATION - NOT USER INPUT] 抬头防止被当成用户授权。
  • 每个子代理类型带输出契约：Plan 必须以 ### Critical Files for Implementation 收尾；worker 必须两段式回话并附好坏例子。
  • 只读角色三层钉死：工具黑名单 + 正文 === CRITICAL: READ-ONLY MODE === + 7 条具体禁令（连 /tmp、重定向符都点名）+ 装配层 omitClaudeMd。
  • "Always synthesize — your most important job"：禁止写 "based on your findings"——那等于把理解外包给 worker。
  • 授权不可转发：worker 停在权限门前、用户批准后，必须新开 agent 并把批准原文放进初始 prompt；这样也把"读过不可信输入的 worker"与"执行特权动作的 worker"分开。
  • 硬数字：并发默认 20、嵌套深度 3、fork 继承完整上下文且不占父上下文。

上下文工程

四条削减路径

  • auto-compact：阈值 = 有效窗口 − 13000
  • /compact：可带自定义指令
  • microcompact：按空闲时间清旧 tool_result
  • reactive compact：prompt-too-long 后重试

缓存与结构耦合

系统提示词里有一个哨兵 __SYSTEM_PROMPT_DYNAMIC_BOUNDARY__，把内容切成静态段与动态段，再按块标 cacheScope。断点是运行时决策：MCP 工具不稳定时就挪到系统提示词。

文件新鲜度

mtime + 内容 hash + "是否完整视图"三件套；部分读不算读过；压缩后作废文件状态，而不是假装还记得。

截断要结构化

Read 默认 2000 行、Bash 20000 字符；Read 走 token-cap 分页并置 truncatedByTokenCap 布尔位——比横幅文案更抗消息重建。

二进制里有什么

尾部 8.4 MB 不是 JS 字节码，而是嵌进去的原生库：libComputerUseSwift.dylib（Swift，x86_64 + ARM64）、libcomputer_use_input.dylib（Rust，构建路径还泄漏了 monorepo 位置）、audio-capture.node。也就是说 computer-use 的实现不在 JS 里。

完整性核对结论：字节码区没有"只存在于那里"的提示词。第一轮算出 43,607 条源码里找不到的串，人工复核后确认属于 Claude Code 提示词的 0 条——其余是 Bun/Rust/JSC 运行时字符串与转义差异造成的假缺口。

动态验证：本地拦截一次真实请求

做法：把 ANTHROPIC_BASE_URL 指向本机的一个小服务器，用空配置目录与假密钥跑一次 claude -p。请求从未离开机器，却拿到了真实请求体。

  • 确认：三个 system 块（计费头不缓存 / 身份 / body）、工具描述确实是两档（Bash 1,097 → 9,438 字符）、# Harness 属于 lean 体、只下发 20 个工具。
  • 纠正：静态分析原以为第三档 system-reminder 说明属于"协调器模式"——真实触发条件是模型的 midConversationSystem 能力位，本机实测走的就是这一档。
  • 顺带发现：-p 默认发 lean 体；加 CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 才得到 27 KB 完整体。

跨六版演化：代码在长，措辞不动

把同一套管线跑在 2.1.272 / 282 / 283 / 284 / 286 / 287 上后对比：7 个小节逐字相同，另外几个只有 1 处条件注入差异；唯一明显新增的子系统是记忆（MEMORY.md 索引常量只在 2.1.287 出现，且真实请求里确实带上了 # auto memory）。

原生层：Ghidra 能反编译什么

三个嵌入库反编译出 5,217 个函数（Ghidra 12 能还原 Swift 符号名）：

库角色证据
libComputerUseSwift无障碍（AX）层AXDispatch.keyCombo/typeText/deleteAtCaret、AXElementAtPoint（向上找可点击祖先）、PhantomCursor、CollisionWatch、WindowCover、截图带排除名单
libcomputer_use_input输入注入层（Rust）CGEventCreate/Post/SetFlags、CGEventKeyboardSetUnicodeString、鼠标/键盘/滚轮事件
audio-capture.nodeCoreAudio 录音AudioUnit / AudioObject，不是 ScreenCaptureKit
权限门在两层：CLI 自身没有 macOS App Sandbox 权限（entitlements 只有 JIT / Apple Events / 麦克风等），OS 级隔离是它主动调 sandbox-exec 起的；seatbelt profile 由 JS 侧拼出来后交给系统执行。

可迁移清单

立刻可做

  1. 提示词块化 + 命名，按"稳定 / 每轮变"分组，块可 null
  2. 每条硬规则补三样：触发条件、反例、替代动作
  3. 红线才用大写 NEVER，且对应真实事故
  4. 写死冲突裁决句
  5. 把 harness 机制写进提示词（谁注入的标签、结果从哪来）
  6. 注入过收口层：白名单 + 长度上限 + truncated/dropped 可观测
  7. 提醒要能自我停止：双阈值 + 可忽略出口 + 连发上限

要改架构才能享受

  1. 表达层可插拔（output style 式），同一意图给三级粒度
  2. 异步子代理契约化：结构化通知 + 禁止预测结果
  3. 并发按读写分型；写同一批文件串行 + worktree 隔离
  4. 授权不可转发；读不可信输入与执行特权动作分角色
  5. 任务板与待办二选一，完成定义可执行
  6. 提示词边界显式标记，让缓存断点可计算
  7. 验证的定义写清楚：proving ≠ confirming
  8. 元功能做成 agent 工作流（记忆整合 / 技能沉淀 / 评测 / 诊断）

局限与未完成

  • 分析对象是本机这一份构建；不同账号/地区/灰度下的提示词可能不同。
  • 动态块的最终拼接只能在运行时确定；本文给的是装配代码与各块原文，不是某一轮真实请求体。
  • 交互式 TUI 未能实测（沙箱禁止 openpty），所以 CLI 变体身份句未验证。
  • JSC 字节码没有反编译（无公开反编译器），只做了完整性对照。
  • 231 个非 chunk 资源（SKILL-*.md 等）未逐个提取；sandbox profile 的默认放行集合未完整还原。
  • 反编译产物只做了符号面与系统 API 归纳，未逐函数审读。
